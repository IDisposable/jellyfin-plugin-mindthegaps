Settings

Choose what the gap scanner looks for. Use the button at the top to go back to the gaps report. Search narrows the sections below to whatever matches; a provider whose settings you already use opens by default.

Sources

Every integration with its own account, list, or credential, one per provider: its toggles, ids, and key all live together instead of split across sections. Collapsed by default; a provider you already use opens on its own.

Checking...
Connecting reads your TMDB watchlist and favorites. Step one opens themoviedb.org in a new tab to approve; step two finishes here. Nothing calls back into this server, so it does not need to be reachable from the internet. TMDB sessions do not expire, so this is a one-time setup. The session can change your TMDB account, so it is stored as a secret and never shown.
Trakt
Episode cross-checks follow your Shows library's metadata fetchers (Dashboard, Libraries, your Shows library, Metadata): each provider you have enabled there is asked for the series' episode list and the lists are merged in your fetcher order, so your preferred provider is the authority for a series. TheMovieDb and TVmaze are keyless; TheTVDB needs its own key (its own section below).
Comma-separated Trakt lists, each a numeric id or a slug (the part after /lists/ in a trakt.tv list URL); the movies and shows on each that you do not own become discovery gaps.
Whose watchlist to read, as the username or profile slug. The profile has to be public. Trakt answers a private profile, an unknown username, and an empty watchlist the same way, so if nothing appears, check the spelling and the profile's privacy.
Create a free API app at trakt.tv/oauth/applications and paste its Client ID. Required for the cross-check and every Trakt list/watchlist above (opt-in per Trakt's terms).
MDBList
Search MDBList for a public list (such as a toplist) and pick it; titles on it that you do not own become discovery gaps.
Your own watchlist, not a community list. The MDBList API key below identifies the account, so there is nothing else to enter.
A free MDBList API key (mdblist.com, under Preferences). Needed to search and read MDBList lists, and to identify your account for the watchlist above.
Discogs
Search Discogs for a record label and pick it; the releases on it that you do not own become gaps.
Discogs addresses a wantlist by username, so the token says who is asking and this says whose list to read. Your own always works; someone else's only if they have made it public.
A Discogs personal access token (Discogs requires authentication to browse the catalog). Create one on discogs.com under Settings, Developers.
OpenLibrary
Comma-separated OpenLibrary subject slugs; the books on each that you do not own become gaps. A subject slug is the last part of an openlibrary.org/subjects/<slug> URL (lowercase, underscores for spaces).
The part after /people/ in an openlibrary.org profile address. Needs no key, but the reading log has to be public (OpenLibrary, Settings, Privacy).
TheTVDB
Your v4 API key from thetvdb.com/dashboard/account/apikey. The TheTVDB cross-check runs when your Shows library lists TheTVDB as a metadata fetcher and this key is set.
Leave blank for the episode cross-check, which only reads the catalog. It is needed to read your account, which today means your favorites: a key-only token is not tied to an account. Find it on thetvdb.com under your account, Subscription.
Needs the key and the PIN above. Expect few results: a favorite is usually a show you already have, so this only surfaces the ones you follow but never acquired.
IMDb
Comma-separated IMDb ids, each a user id (ur..., meaning that user's watchlist) or a list id (ls...). A full imdb.com address can be pasted instead. Needs no key, but the watchlist or list has to be public (IMDb, Your Account, Privacy). The newer profile addresses that read imdb.com/user/p.<random>/ carry no usable id: open the watchlist from Your Lists and take the ls... id out of its address.
IMDb lists hold either titles or people. A people list is read as a filmography seed instead: every unowned film and series each named person made becomes a Creator works gap, which is how you track a director you own nothing by. Same ids as above; a titles list is unaffected. One people list is many filmographies, so at most 50 people per list are followed per scan, and the Creator works relevance floors still apply.
JustWatch
Off by default: a like is a weaker signal than a watchlist entry.
JustWatch issues no api keys and its published API covers streaming availability only, so a personal list needs your own session token. Sign in at justwatch.com, open the browser developer tools, Network tab, reload My Lists, pick any request to apis.justwatch.com, and copy the Authorization header value after "Bearer ". The token expires, so it has to be replaced now and then; the scan logs a warning and carries on when it does.

Where to watch

Powers the "Where to watch" links and the report's "Hide items with no sources" filter. Look-ups run on demand per item, or as a background pass from the report (the "Look up where to watch" button), never during the scan. The "Refresh where to watch" scheduled task keeps it current.
How long a looked-up "where to watch" result stays fresh before it is refreshed. A stale result is still shown instantly while a refresh runs behind the scenes, so this only trades how current the data is against how often TMDB is hit. Default 24.

Images

Posters, album and book covers, and streaming-service logos are fetched from their providers once and served from the server's cache folder, which spares the providers the traffic and keeps your browsers from contacting them. Only images from the providers the plugin reads are kept, and each is limited to 5 MB. An image the server cannot get at once is loaded by the browser from the provider instead. Off, browsers load them from the providers directly. Off by default.
The most the image cache may hold. The "Trim the image cache" scheduled task (at startup and daily) deletes the oldest images once it is over, and nothing more is fetched between runs if it reaches twice this size. The server's own daily cache task also removes any image not used for 30 days. Default 500.

Diagnostics

Logs every external API request and response to the server log. Turn this on to debug a source or acquisition target that is not behaving, then turn it back off. Off by default to keep the log quiet; api keys and tokens are never logged.

Limits

Caps how many similar titles each owned item contributes (recommended max 100).
A recommended ("similar") title must have at least this many TMDB votes to surface, trimming the obscure long tail of the discovery feed. 0 shows everything; raise it (for example 500 or 1000) to keep only well-known suggestions.
Hides a movie credit with fewer TMDB votes than this. 0 shows every credit. Kept separate from the filmography scan floor because that floor also hides every show (TV credits carry no vote count).
Hides a TV acting credit spanning fewer episodes than this. One-episode credits are guest spots and talk-show appearances; 2 keeps recurring roles. 0 shows every credit.
Caps how many missing episodes are listed per show. 0 lists them all.
Filmography and recommendation scans rotate stalest-first within this cap, so coverage builds up over runs; raise this to cover a large cast and crew faster (each person is one cached TMDB lookup; recommended max 10000).
Keeps Creator works actionable on a large library: a cast credit must have at least this many TMDB votes to surface, which drops obscure and unreleased films. 0 shows everything; raise it (for example 500 or 1000) to trim to only well-known films. Directing/writing credits are always shown.
Drops minor (deeply billed) acting roles, so a bit part is not counted as the person's work. 0 keeps any billing; for example 10 keeps only roles billed in the top 10. Does not affect directing/writing.
